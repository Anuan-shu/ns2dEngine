# ECS 设计与验证

本轮改造补齐实体身份、组件存储、遍历期间的结构变更和系统成员同步。原有 `CreateEntity`、`AddComponent`、`GetComponent` 和 `Kill` 的基本调用方式继续可用。所有新增源码注释使用中文，修改过的旧源码保持 UTF-8 编码。

## 实体身份与生命周期

实体句柄包含注册表身份、槽位 ID 和版本号。ID 是存储位置，不再单独代表实体身份。销毁提交时递增版本号，然后才能复用该 ID；旧句柄不会读取、修改或销毁复用槽位的新实体。不同注册表的同号实体也不相等。

`IsValid()` 检查注册表生命周期、所属注册表、槽位存活状态和版本号。注册表析构后，实体成员函数先检查弱生命周期标记，避免解引用已析构的注册表。注册表禁止复制和移动，确保身份和地址稳定。

```cpp
auto old = registry.CreateEntity();
old.AddComponent<TransformComponent>();
registry.Update();

old.Kill();
// 此时 old 仍有效，但 IsPendingRemoval() 为 true。
registry.Update();
// 提交后 old.IsValid() 为 false，后续即使复用同一个 ID 也不会重新有效。
```

`Kill()` 对重复销毁和失效句柄安全地忽略。待销毁实体不能再增删组件、改标签或改分组；已有组件在销毁提交前仍可读取，供当前事件回调使用。默认构造的句柄，以及直接用整数构造的句柄都无效。业务代码应通过注册表取得实体。

保留了公开的 `entity.registry` 指针以兼容原有代码，但不要自己修改它，也不要在注册表析构后直接解引用它；实体成员函数会做生命周期校验，裸指针直接调用不会获得这种保护。框架仍要求调用者保证组件和系统中保存的其他外部指针有效。

## 组件池与查询

组件池使用三个数组：

- 稠密组件数组：只保存实际存在的组件，不再默认构造一百个空组件。
- 稠密实体 ID 数组：记录每个组件属于哪个实体。
- 稀疏索引数组：用实体 ID 定位稠密数组下标。

删除时用末尾组件填补空位，并同步修正被移动实体的索引，最后移除末尾元素。查询和删除定位是 O(1)；插入通常为摊销 O(1)，稀疏索引第一次扩展到更大 ID 时需要初始化新增区间。这里的 ID 是注册表分配的紧凑槽位，不面向任意巨大外部 ID。

清空时同时清除数据和两类索引；重新插入不再把容量误当作有效元素数量。支持没有默认构造函数、不能复制但可以移动的组件。组件的移动赋值应当不抛异常，尤其是交换删除时；不承诺任意用户组件抛异常后的整个操作回滚。

| 接口 | 失败时的行为 |
| --- | --- |
| `entity.IsValid()` | 返回 false |
| `HasComponent<T>()` | 无效实体或缺失组件返回 false |
| `TryGetComponent<T>()` | 无效实体或缺失组件返回 nullptr |
| `GetComponent<T>()` | 无效实体抛 invalid_argument；缺失组件抛 out_of_range |
| `GetSystem<T>()` | 未注册系统抛 out_of_range |
| `TryGetEntityByTag()` | 未找到返回空 optional |
| `GetEntityByTag()` | 未找到抛 out_of_range |

只读 Registry 的组件查询返回只读指针或引用。Entity 是句柄，其 const 性不代表它指向的组件只读，系统可以通过只读实体视图修改组件数据。

当前组件类型上限仍是 32。组件类型 ID 分配在达到上限时抛出受控异常，不再越界访问签名。类型 ID 是进程内注册编号，不应作为持久化场景的字段编号。

## 结构变更与提交边界

普通组件数值修改立即生效。新增/替换/移除组件、标签和分组在 `Defer()` 保护区中排队，在保护区外立即修改存储。新建实体立即取得句柄，但只有 `Update()` 后才进入系统。实体销毁始终延迟到 `Update()`。

保护区内不能查询尚未提交的新组件，也不能依赖排队的新标签或分组。

```cpp
{
    auto deferred = registry.Defer();
    for (auto entity : registry.GetSystem<MovementSystem>().GetSystemEntities()) {
        // 数值修改立即生效。
        entity.GetComponent<TransformComponent>().position.x += 1;
        // 删除组件排队；当前遍历仍能安全使用原组件。
        entity.RemoveComponent<RigidBodyComponent>();
    }
}
registry.Update();
```

也可以用自动建立保护区的接口：

```cpp
registry.Each<MovementSystem>([](Entity entity) {
    entity.RemoveComponent<RigidBodyComponent>();
});
registry.Update();
```

保护区可以嵌套；析构只解除保护，不自动提交。异常退出后仍能正常提交此前排队的命令。保护区内调用 `Update`、`Clear` 或增删系统会抛 logic_error，防止遍历中的引用和迭代器失效。

`Update()` 先提交销毁，再按请求顺序处理结构命令，最后对发生变化的实体重新匹配系统。目标版本已被销毁的命令会跳过，不能误作用于后续复用的实体。它是有序提交机制，不是具有整体回滚能力的数据库事务；提交过程中发生配置冲突等异常时，之前成功执行的命令保留，后续命令仍留待处理。

游戏的输入回调、每个物理步、帧末系统更新及调试 GUI 已接入保护区。子弹碰撞体先在局部配置为触发器，再把完整组件加入队列，避免提交前读取新组件。

直接调用某个系统的 Update 或自行遍历组件时，调用者也需要建立保护区，或者使用 `Each`。不要在未保护的遍历中增删同类型组件。

## 系统成员一致性

系统实体数组配有句柄到下标的索引，重复同步不会重复加入，移除成员时也会修正补位索引。新增或移除组件会把实体标记为需要重新匹配，下一次 `Update()` 按最终签名加入或移出所有相关系统。

系统注册后签名冻结；修改系统要求应移除并重新注册系统。后注册的系统会立即匹配已经提交的存活实体。重复注册同类系统会明确抛错。移除系统后，其事件订阅仍需要调用者管理；本轮未重构 EventBus 的取消订阅机制。

`GetSystemEntities()` 返回只读引用，避免每次复制整个数组。引用与迭代器不能跨下一次 `Update()` 或 `Clear()` 保存，移除系统后也不能继续使用其视图。组件引用同样不能跨组件池的结构变更保存，长期保存应使用实体句柄并重新查询组件。数组不保证稳定顺序，删除时会用末尾实体补位。

## 标签、分组和清空

每个实体最多一个标签和一个分组，与原模型一致。标签全局唯一，重复占用会失败；改名或换组会清除旧关联，重复设置相同值不会重复加入。未知分组查询返回空数组，销毁同步清理双向索引。

`Registry::Clear()` 清空实体、组件、成员索引、标签、分组及待提交命令，保留已注册系统和组件类型，可以随后创建新场景。旧句柄全部失效，槽位版本不重置。

## 验证范围

`tests/ecs_tests.cpp` 不需要 SDL，覆盖：

- 零容量组件池扩容、覆盖、交换删除、重复删除、清空重建，以及只移动组件。
- 3000 次固定种子的组件池随机操作，与普通映射逐次对照。
- ID 复用、旧句柄误用、跨注册表访问、注册表先析构和清空重建。
- 运行时增删组件、后注册系统、重复同步、系统签名冻结和缺失查询。
- 嵌套保护区、异常退出、大量排队新增、销毁优先和命令取消。
- 1200 次固定种子的注册表随机操作，与生命周期和系统成员参考模型对照。
- 标签改名、唯一性冲突、换组、重复移除及组件类型上限。

构建与运行全部已配置测试：

```powershell
cmake --build .build/cmake --parallel 4
ctest --test-dir .build/cmake --output-on-failure
```

也可只构建不依赖 SDL 的 ECS 和几何测试：

```powershell
cmake -S . -B build -G "MinGW Makefiles"
cmake --build build
ctest --test-dir build --output-on-failure
```

现有物理集成测试继续运行；游戏冒烟测试分别运行第 2 关和第 3 关，并注入空格按键验证真实子弹创建回调。无窗口测试验证加载与运行链路，不代替人工画面和操作体验验收。

框架目前按单线程游戏循环设计。组件类型编号分配使用原子变量，其他注册表、组件池和系统操作并不因此具有线程安全性。本轮没有引入 Archetype、多线程任务调度或稳定地址组件存储。

面试时可以围绕一个具体场景讲解：脚本保留实体 A 的句柄，A 被销毁后其 ID 分配给 B；通过注册表身份和版本号校验，旧句柄不能修改 B。在系统遍历中移除组件时，命令队列保留当前组件与成员视图，提交后再更新系统签名匹配，避免访问已删除组件或漏掉新加入的实体。
