# 轻量二维物理系统

本项目现在具备“固定步长 → 受力积分 → 宽阶段筛选 → 精确碰撞 → 冲量响应 → 位置修正 → 游戏事件”的完整基础流程。定位是适合学习、面试展示和简单游戏的二维平移物理模块。

## 已实现的能力

| 项目 | 实现 |
| --- | --- |
| 形状 | 任意角度的矩形 OBB、圆形；三种形状组合均可检测 |
| 空间变换 | 位置、局部偏移、缩放、旋转统一计算；调试绘制复用相同几何 |
| 宽阶段 | 世界 AABB，沿 X 轴排序扫描，排除远距离物体 |
| 窄阶段 | 矩形 SAT；圆心距离；圆与矩形最近点及内部包含处理 |
| 刚体 | Static、Kinematic、Dynamic；无刚体的碰撞体作为静态物体 |
| 动力学 | 质量、力、重力系数、线性阻尼、瞬时冲量；半隐式欧拉积分 |
| 碰撞响应 | 法线冲量、恢复系数、库仑摩擦、按逆质量分配穿透修正；6 次迭代 |
| 触发器 | 产生事件，不改变物体位置或速度；现有子弹自动使用触发器 |
| 过滤 | category/mask 双向位掩码过滤 |
| 时间 | 每步 1/120 秒；每帧最多补算 8 步，超载时丢弃多余积压 |
| 游戏衔接 | 每对接触每物理步发一次事件；待销毁子弹不会继续伤害其他目标 |

## 文件入口与调用关系

- `src/Components/ColliderComponent.h`：单实体单形状，保存尺寸、偏移、过滤和触发配置。
- `src/Components/BoxColliderComponent.h`：旧名称的类型别名，现有调用不需要迁移；两种名字指向同一组件池。
- `src/Components/RigidBodyComponent.h`：速度、质量、受力和材质。
- `src/Physics/Physics2D.h`：不依赖 SDL/ECS 的几何、宽阶段、积分和响应算法。
- `src/Physics/EntityShape.h`：将实体组件组合成世界空间形状。
- `src/Systems/MovementSystem.h`：每步积分和原有地图边界逻辑。
- `src/Systems/CollisionSystem.h`：筛选候选对、建立接触、求解、发送事件。
- `src/Game/Game.cpp`：固定时间步调度。Lua 更新在每个物理步的积分之前执行。

每步开始运行 Lua，然后执行 `velocity += acceleration * dt`、`position += velocity * dt`。对候选碰撞计算法线和穿透深度，只对实体碰撞应用响应，最后发送事件并提交实体销毁。事件订阅改为初始化时一次注册，避免每帧重建和第一帧按键无订阅的问题。

## 坐标与旋转约定

位置仍然是图片左上角，角度单位是度。屏幕 Y 轴向下，正角度在画面上顺时针，和 SDL 一致。

`offset` 是未经缩放的局部偏移。矩形由宽高定义；圆形的 `offset` 指向局部包围正方形的左上角，局部圆心为 `offset + (radius, radius)`。

有 Sprite 的实体绕图片中心旋转，以匹配 SDL；没有 Sprite 时绕碰撞体自身中心旋转。非均匀缩放的圆仍按圆处理，半径乘以两个缩放绝对值中的较大值，不模拟椭圆。负缩放的碰撞几何可以计算，但原有图片渲染没有同步增加负尺寸翻转支持，关卡应优先使用正缩放。

与旧版不同，边缘接触也算接触，以便支撑静止物体；允许约 0.01 像素的穿透容差来减少抖动。

## Lua 配置示例

```lua
components = {
    transform = {
        position = { x = 200, y = 100 },
        scale = { x = 1, y = 1 },
        rotation = 30
    },
    rigidbody = {
        type = "dynamic", -- static / kinematic / dynamic
        mass = 2,
        velocity = { x = 60, y = 0 }, -- 可省略，默认零
        gravity_scale = 1, -- 默认 0，兼容原俯视游戏
        restitution = 0.6, -- 0 无弹性，1 完全弹性
        friction = 0.4,
        linear_damping = 0.1
    },
    collider = {
        shape = "box",
        width = 40, height = 30,
        offset = { x = 0, y = 0 },
        is_trigger = false,
        category = 1, mask = 4294967295
    }
}
```

圆形配置为 `collider = { shape = "circle", radius = 18 }`。旧 `boxcollider` 配置继续有效，也可增加 `is_trigger/category/mask`。同时配置两个字段时 `collider` 优先。一个实体只能有一个碰撞体，不是复合碰撞体。

无刚体的碰撞体位置不由物理解算改变；需要配置静态材质时可显式添加 `rigidbody = { type = "static", ... }`。运动学刚体按速度移动，不受力、冲量或位置修正影响，但可以推动动态刚体。动态质量应大于零，非正质量作为不可移动处理。

默认重力向量为 `(0, 980)` 像素/秒²；物体需要 `gravity_scale = 1` 才会下落。C++ 可设置 `MovementSystem::gravity`。力的单位与“质量 × 像素/秒²”一致。

Lua 更新回调中可以调用：

```lua
add_force(entity, 100, 0)     -- 持续力：每个物理步都调用
apply_impulse(entity, 30, 0)  -- 瞬时冲量：仅在需要的一次调用
```

累积力每次积分后清零；如果一帧没有物理步，力不会提前丢弃。旧 `set_velocity` 仍有效，但每步强制设速度会覆盖上一步碰撞响应，应只用于需要这种控制方式的物体。

## 演示与验证

在项目根目录运行生成的游戏：

```powershell
.\.build\cmake\ns2dEngine.exe --physics-demo
```

演示关卡 `assets/scripts/level3.lua` 使用轮廓显示旋转矩形、圆形、斜面和触发区域。绿色为实体碰撞体，黄色为触发器；D 开关调试显示，Esc 退出。不带参数仍进入原第 2 关。原关卡中的碰撞体现在默认具有实体阻挡效果，若希望某物体仅触发事件，应设置 `is_trigger = true`。

只构建算法测试，不需要 SDL：

```powershell
cmake -S . -B build -G "MinGW Makefiles"
cmake --build build
ctest --test-dir build --output-on-failure
```

```powershell
cmake -S . -B .build/cmake -G "MinGW Makefiles" `
  -DSDL2_INCLUDE_DIR="$PWD/.build/SDL2-2.30.9/x86_64-w64-mingw32/include/SDL2" `
```

测试覆盖几何边界、旋转后的 AABB 假阳性、包含关系、法线方向、质量与动量/能量、摩擦、静态/运动学响应、固定步长、10 秒静止稳定性，以及 200 个固定种子随机形状的宽阶段漏检检查。ECS 测试使用真实 DamageSystem 验证单发子弹不重复扣血；游戏冒烟测试用 SDL dummy 驱动分别运行原关卡与演示关卡各 180 帧，不打开窗口。冒烟测试验证加载与运行链路，不等于人工视觉和游戏手感验收。

现有 Visual Studio 工程仍保留原开发者的 SDL 绝对路径；这次提供可复现的 MinGW/CMake 验证方式，不要求本机存在原 G 盘路径。GCC 16 构建游戏时仅为附带旧 sol 库关闭过早的模板体检查，不修改第三方源码。

## 能力边界与面试表述

这不是 Box2D 的替代品。目前不计算接触点力矩、角速度和转动惯量；旋转角度由脚本控制，碰撞只改变平移运动。也没有连续碰撞检测 CCD、关节、休眠、接触缓存与热启动。高速小物体仍可能穿透薄障碍，120 Hz 只能降低概率，不能保证避免。宽阶段在大量重叠物体下最坏仍为 O(n²)，也没有承诺复杂堆叠的工业级稳定性。

可以在面试中这样描述：

> 我在 ECS 上实现了轻量二维物理模块。用固定步长和半隐式欧拉更新运动，宽阶段使用 AABB 排序扫描，窄阶段支持 OBB 的 SAT、圆与圆、圆与矩形。检测输出法线和穿透深度，再通过逆质量加权的冲量、摩擦和位置修正处理响应；触发器走事件，不进入响应。当前约束是只解算平移，没有角动量和 CCD，并通过几何、动力学、ECS 与游戏加载测试验证。
